# 리뷰 분류 벤치마크 v1 — 정답 기준서

리뷰 분류(C3)가 얼마나 맞는지 **매번 같은 시험으로** 재기 위한 데이터입니다. 발표용 온기한식 40건(`data/synthetic/`)과는 따로 둡니다.

- 만든 사람: 이건영 · Claude (HCX로 만들지 않음 — 시험을 볼 모델이 문제를 쓰면 공정하지 않아서)
- 모두 지어낸 합성 리뷰입니다. 실제 손님 리뷰·실제 가게가 아닙니다.
- **연습용(dev) 360건** (기본 300 + 컨셉 60): 보면서 프롬프트·kiwi 규칙을 고쳐도 됩니다.
- **시험용(test) 240건** (기본 200 + 컨셉 40): 보면서 고치지 않습니다. 점수를 낼 때만 엽니다. 발표에서 말하는 정확도는 이 점수입니다.
- 한 번 정한 정답은 바꾸지 않습니다. 정답이 틀렸으면 `v2`로 올리고 바꾼 줄을 기록합니다.

## 1. 감정 (sentiment)

리뷰 **전체의 느낌**으로 정합니다. 별점은 참고만 합니다 (별점과 내용이 다르면 내용을 따릅니다).

| 값 | 뜻 | 예 |
|---|---|---|
| `positive` | 칭찬만 | "맛있어요 또 시킬게요" |
| `negative` | 불만만 | "다 식어서 왔어요" / "다신 안 시켜요" (주제 없어도 불만) |
| `mixed` | 칭찬과 불만이 함께 | "맛은 좋은데 양이 적어요" |
| `neutral` | 칭찬도 불만도 아님 | "보통이에요", "그냥 그래요", "잘 받았습니다" |

## 2. 주제 13개와 칭찬(+)·불만(-)

리뷰에 나온 주제를 **빠짐없이** 적고, 주제마다 칭찬(+)인지 불만(-)인지 적습니다. 주제 사전에 없는 내용(재주문 의사, 사장님께 인사 등)은 적지 않습니다.

| id | 이름 | 넣는 것 | 헷갈리는 경우 |
|---|---|---|---|
| `portion` | 양 | 양, 구성 대비 양, 개수 | "가격에 비해 양이 적다" → portion- 과 price- 둘 다 |
| `taste` | 맛 | 맛, 간(짜다·싱겁다·달다), 냄새, 신선도 맛 | 바삭·눅눅·질김은 texture |
| `price` | 가격 | 가격, 가성비, 할인 | "비싼 만큼 맛있다" → price- , taste+ |
| `delivery_time` | 배달 시간 | 배달 주문이 늦게·빨리 옴 | 매장에서 늦게 나온 건 wait_time |
| `texture` | 식감 | 바삭·눅눅·질김·퍽퍽·부드러움·딱딱 | |
| `temperature` | 음식 온도 | 식음·미지근·따뜻함·음료 시원함·얼음 녹음 | "불어서 왔다"(면)는 texture |
| `packaging` | 포장 상태 | 샘·쏟아짐·찌그러짐·뚜껑·포장 꼼꼼함 | "포장해 갔다"(포장 주문)는 주제 아님 |
| `missing_item` | 포장 누락 | 빠진 메뉴·덜 온 개수·잘못 온 메뉴(순살↔뼈 포함)·수저 누락·주문한 추가 옵션(샷 추가 등)이 빠짐 | 요청사항 칸의 부탁(맵기·간·디카페인)을 안 들어준 건 service- |
| `service` | 응대 | 직원·사장님 응대, 전화, 요청사항 반영, 서비스(덤) 감사 | "서비스로 음료 주셨어요" → service+ |
| `hygiene` | 위생 | 청결, 이물질, 매장·식기 깨끗함 | 음식 모양이 "깔끔"한 건 주제 아님 |
| `menu` | 메뉴 구성 | 메뉴 종류, 반찬 가짓수·구성, 메뉴 품절·변경 | 반찬 맛은 taste |
| `atmosphere` | 매장 환경 | 좌석·공간·인테리어·분위기·소음·주차 (방문) | |
| `wait_time` | 매장 대기 | 매장·포장 수령에서 기다린 시간, 웨이팅 | 배달은 delivery_time |

같은 주제에 +와 -를 함께 적는 건, 리뷰가 **같은 점을** 칭찬도 하고 불만도 할 때뿐입니다 ("튀김은 바삭한데 감자는 눅눅해요" → texture+, texture-).

## 3. 어려운 유형 태그 (tags)

점수를 유형별로 나눠 보려고 붙입니다. 하나의 리뷰에 여러 개 붙을 수 있습니다.

| 태그 | 뜻 | 예 |
|---|---|---|
| `plain` | 평범한 한 가지 이야기 | "맛있어요" |
| `multi` | 주제 2개 이상 | |
| `negation` | 부정문으로 칭찬·불만 | "하나도 안 식었어요"(+), "안 바삭해요"(-) |
| `typo` | 오타·띄어쓰기 틀림 | "맛잇어요", "늣게왔어요" |
| `slang` | 줄임말·인터넷 말투·이모티콘 | "존맛", "ㅋㅋ", "실화냐", "^^" |
| `sarcasm` | 반어 | "배달 참 빠르네요, 1시간 ㅎㅎ" |
| `rating_mismatch` | 별점과 내용이 다름 | ★5 인데 불만 |
| `short` | 10자 안팎으로 아주 짧음 | "굿", "별로" |
| `long` | 세 문장 이상 길게 | |
| `no_topic` | 주제 사전에 맞는 주제가 없음 | "또 시킬게요", "번창하세요" |
| `compare` | 예전·다른 곳과 비교 | "예전보다 양이 줄었어요" |
| `visit` | 매장 방문 리뷰 (naver_place) | |
| `request` | 요청사항 관련 | "요청사항 잘 들어주셨어요" |
| `pii` | 전화번호·이메일 같은 개인정보가 섞임 (가림 시험) | |
| `concept` | 컨셉 리뷰: 의성어·동물 흉내, 삼행시, 점수표·체크리스트, 편지·일기·사극·군대 말투, 노래 개사, 과장 | "맛있으면 짓는 개: 왈왈왈" |
| `template` | 리뷰 이벤트용 틀에 박힌 글 | "리뷰 이벤트 참여합니다 맛있어요" |
| `platform` | 가게가 아닌 배달 기사·배달앱 이야기 | "기사님 친절", "쿠폰 적용 안 됨" |
| `question` | 리뷰에 질문만 | "매장에서도 먹을 수 있나요?" |

## 5. 컨셉 리뷰 정답 정하는 법

실제 배달앱 리뷰 말투를 조사해서 유형만 가져오고 글은 새로 썼습니다 (실제 리뷰 원문을 복사하지 않음).

- 말투가 특이해도 **무엇을 칭찬·불만했는지**로 정합니다. "맛있으면 짓는 개: 왈왈" → 맛+, "맛 10/10 양 6/10" → 맛+ 양-.
- 점수·별 표기는 높으면 +, 낮으면 - (5점 중 3 이하, 10점 중 6 이하는 -). 중간이라 판단이 어려우면 적지 않습니다.
- 배달 기사님 친절, 배달앱 쿠폰·결제 오류처럼 **가게가 한 일이 아닌 것**은 주제로 적지 않습니다 (감정은 글의 느낌대로).
- 리뷰 이벤트 덤·손편지·서비스 메뉴처럼 **가게가 챙겨 준 것**은 응대(service)+입니다.
- 질문만 있는 리뷰는 보통(neutral)입니다.
- 감탄만 있고 무엇이 좋은지 없으면("천사세요?", "😋😋") 주제 없이 칭찬입니다.
- 반어("소금을 들이부으셨네요")는 뜻을 따라 불만으로 적습니다.

## 4. 채점

- 감정 정확도: 감정이 정답과 같은 비율
- 주제 정밀도: 모델이 낸 (주제, +/-) 중 정답에 있는 비율 / 재현율: 정답 (주제, +/-) 중 모델이 찾은 비율
- 주제별·태그별 점수를 따로 봅니다 (어느 주제, 어떤 유형에서 틀리는지)
- 실행: `python -m scripts.eval_benchmark --split dev` (규칙 분류) · `APP_MODE=live python -m scripts.eval_benchmark --split test`
